# 建筑案例研究型交互设计说明

## 目标

在不改变现有路由、导航、整体布局、视觉系统和图片素材的前提下，将 `/building` 从静态建筑图片展示升级为研究型交互展示。用户可以从四座建筑入口进入同页分析状态，查看放大图片及概括性研究信息，并继续阅读嵌瓷元素提取内容。

## 范围

- 仅增强 `/building` 页面。
- 保留 `/building` 路由、现有页首、传统来源区、四张建筑图片和嵌瓷元素提取区。
- 不修改 `/modern`、导航、其他案例或共享视觉系统。
- 不新增页面、外部素材、弹窗、复杂动画或具体历史断言。

## 页面信息结构

页面保持以下研究动线：

1. 传统来源
2. 建筑案例
3. 嵌瓷元素提取

“建筑案例”位于传统来源说明之后，由现有四张建筑图片组成。默认状态保留两列展陈布局。选中建筑后，在建筑入口下方展开研究详情，不改变后续元素提取模块的顺序。

## 建筑案例交互

### 默认状态

- 四座建筑继续以两列图片入口展示。
- 每个入口显示建筑图片和名称。
- 卡片使用按钮语义，支持鼠标点击和键盘操作。
- 默认不显示研究详情。

### 展开状态

- 点击建筑卡片后，在案例区下方展开详情。
- 详情采用左右分栏：左侧显示所选建筑的大尺寸图片，右侧显示分析信息。
- 右侧依次展示建筑名称、建筑类型、嵌瓷应用位置、文化寓意。
- 选中卡片使用现有朱红细线和文字状态表达，不引入新的高饱和色或浮层。
- 点击另一张建筑卡片时，详情直接切换到新建筑。
- 再次点击当前建筑卡片时关闭详情，恢复默认状态。
- 仅使用轻量状态变化，不添加复杂过渡动画。

## 嵌瓷元素提取

元素提取保持三列展陈结构，并将内容明确为可阅读的研究条目。

### 色彩提取

- 朱红：关联礼制、喜庆与建筑视觉焦点。
- 釉绿：连接自然、生机与传统彩瓷的釉色特征。
- 金色：强化庄重、光泽与重要装饰部位的层级。

### 纹样提取

- 龙凤：表达祥瑞、秩序与祝愿。
- 花鸟：连接自然生命、繁盛与日常审美。
- 卷草纹：通过连续曲线形成延展、连接与装饰节奏。

### 拼接结构提取

- 瓷片排列方式：依据轮廓方向组织碎片，形成连续边界和视觉走势。
- 层叠关系：以前后覆盖建立纹样层次和局部厚度。
- 高低起伏结构：通过不同高度塑造立体明暗和远近关系。

## 组件与数据边界

- `Building.jsx` 继续负责 `/building` 页面组合与交互状态。
- 新增 Building 专用的建筑案例交互组件，负责入口选择、展开详情和关闭行为。
- 建筑研究字段保存在现有 `architectureCase.sourceImages` 数据项中。
- `ModernCaseDetail.jsx` 仅增加可注入建筑案例展示内容的兼容接口，默认行为保持不变，确保 `/modern` 不受影响。
- 元素提取数据继续使用 `architectureCase.extractions`，新增结构化条目供三张提取卡片展示。

## 可访问性

- 每张建筑入口使用原生 `button`。
- 使用 `aria-pressed` 表示当前选中状态。
- 展开详情通过语义化区域和标题建立名称关系。
- 图片保留建筑名称作为替代文本。
- 关闭行为与再次点击当前按钮保持一致，不另加不必要的图标按钮。

## 测试与验收

自动化测试覆盖：

1. 默认显示四张建筑入口且研究详情关闭。
2. 点击建筑入口后显示对应名称、类型、位置和寓意。
3. 点击另一座建筑后详情内容正确切换。
4. 再次点击当前建筑后详情关闭。
5. 三张元素提取卡片分别显示指定研究条目。
6. `/modern` 现有案例选择与详情行为保持通过。

浏览器验收使用 PC 端 1280×720：

- 四图两列布局保持完整。
- 展开区为左图右文，没有遮挡或横向溢出。
- 图片正常加载，文字层级清晰。
- 点击、切换、关闭均稳定。
- 控制台没有相关错误或警告。
- `npm test -- --run` 与 `npm run build` 均成功。
